| # | Problem | Fix | Files |

| 1 | **Pay-on-delivery orders never reduced stock**, so the same item could be sold again and again. This is the live mode. | Stock is reserved inside the locked checkout transaction. | 4 | **Admin "revenue today" was always ₦0 in POD mode, and "today" was a UTC day.** | Revenue counts `paid` and `collected` orders. "Today" starts at midnight in Lagos. | `app/admin/(authed)/page.tsx`, `lib/utils.ts` |

## Speed and scalability
- **Fewer user lookups:** the current user is looked up once per page view instead of 2–4 times (`React.cache` in `lib/session.ts`).
- **Smaller listing queries:** the home and shop pages fetch only the columns a product card needs, not descriptions or search vectors (`lib/product-queries.ts`).
- **Cheaper `/orders` page:** it used to run an UPDATE over the whole orders table, unawaited, on every visit. It now expires only that user's stale orders, awaited.
- **New indexes:**
  - `products(seller_id)`, used on every seller page;
  - `orders(payment_status, created_at)`;
  - `escrow_ledger(seller_id, type)`.
- **Lighter font CSS:** only the latin and latin-ext Nunito files load; cyrillic and vietnamese are dropped.
- **Removed a deprecated Neon option** that logged a warning on every cold start.

## Recommended next (not done)
- **Make public pages cacheable.** The header reads the login cookie on the server, which makes every public page fully dynamic and adds one database hit per view. Moving the header's account bit to a small client component would let the home and shop pages be cached at Vercel's edge (`revalidate = 60`). This is the biggest speed win left, especially on 3G.
- **Add an `order_items` table** with `seller_id`. Seller pages currently scan every order's JSON to find their items. This is fine now but slows down as orders grow.
- **Stop `db:push` from clobbering search.** Model `search_vector` as a `customType('tsvector')` so drizzle stops trying to change it.
